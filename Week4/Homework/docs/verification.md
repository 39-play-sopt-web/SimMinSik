# 게시판 테스트 메모

11월 5일. 글 작성·조회·수정·삭제는 구현하면서 실제 API로 확인함.
실패 응답이나 조회 지연을 확인할 때는 로컬 모의 API(5199)에 검증 화면(5175)을 연결해서 테스트함.

## 요청이 실패하거나 늦게 올 때

| 상황 | 확인한 결과 |
| --- | --- |
| 회원 코드 발급 실패 | 오류 안내가 뜨고 선택한 파트로 다시 시도할 수 있음 |
| 스크롤 중 다음 페이지 요청 실패 | 먼저 불러온 글 10개는 그대로 남고 자동 요청은 멈춤 |
| 다음 페이지가 정상 응답하도록 바꾼 뒤 재시도 | 다음 글 10개가 붙고 마지막 페이지 안내가 뜸 |
| 첫 검색 응답을 1.5초 늦추고 바로 다시 검색 | 첫 응답이 나중에 와도 두 번째 검색 결과가 그대로 남음 |
| 글 수정 요청에 403 반환 | 오류 안내가 뜨고 입력한 제목과 본문이 남아 있음 |

## 재시도 횟수 비교

목록과 상세의 재시도 설정이 달라 `queryClient.ts`에서 한 번에 관리하도록 정리함.
4xx는 한 번만 요청하고, 그 외 오류는 최대 두 번 더 시도함.

Node에서 `QueryObserver`에 실패하는 요청을 연결하고 호출 횟수를 셈.
변경 전은 브라우저 기본값에 맞춰 `retry: 3`으로 두고, 변경 후는 과제의 `queryClient.ts`를 불러옴.
재시도 사이의 대기 시간은 0으로 두고 비교함.

| 응답 | 변경 전 정책의 호출 횟수 | 현재 설정의 호출 횟수 |
| --- | --- | --- |
| 400 | 4 | 1 |
| 401 / 403 / 404 | 비교하지 않음 | 각 1 |
| 503 | 비교하지 않음 | 3 (최초 1회 + 재시도 2회) |

참고한 문서 · [TanStack Query의 재시도 설정](https://tanstack.com/query/latest/docs/framework/react/guides/query-retries)

## 글을 수정하고 돌아왔을 때

수정은 성공했는데 목록에 돌아오면 예전 제목이 보였음.
진행 중인 조회를 취소하고, 수정 응답으로 상세와 목록에 저장된 글부터 바꾸도록 수정함.
제목이 바뀌면 검색 결과에 포함되는 글도 달라질 수 있어서 열려 있지 않은 목록까지 다시 요청함.

- 브라우저에서 제목과 본문을 수정한 뒤 상세와 목록을 열어봄. 새로고침 없이 수정 내용이 보였음.
- `useUpdatePost`의 성공 콜백을 따로 실행하고 조회 응답을 늦춰 봄. 상세와 목록의 두 번째 페이지에 있던 글은 응답을 기다리는 동안에도 바뀌었고, 이전 캐시 객체와 `pageParams`는 그대로였음.
- 예전 제목과 새 제목의 검색 결과를 각각 저장해 둔 뒤 수정해 봄. 재조회 후 예전 검색 결과에서는 글이 빠지고 새 검색 결과에는 들어갔음. 상세로 돌아갈 때 기존 검색어도 유지됐음.

## 헤더와 로그아웃

- WEB으로 코드를 발급하면 헤더에 WEB과 목록·글쓰기·로그아웃 메뉴가 보임. 새로고침해도 WEB 표시가 남음.
- 로그아웃하면 발급 화면으로 돌아감. 다시 목록을 열면 파트 표시와 로그아웃 버튼이 사라지고, 글쓰기를 누르면 코드 발급 안내가 뜸.
