# 예외 동작 확인

2026년 11월 5일에 확인했습니다.

실제 API의 작성·조회·수정·삭제는 앞선 구현 단계에서 확인했습니다.
아래 실패 상황은 실제 게시판에 영향을 주지 않도록 로컬 모의 API에서 재현했습니다.
검증 화면은 localhost:5175, 모의 API는 localhost:5199를 사용했습니다.
과제 실행 주소와 .env는 변경하지 않았습니다.

| 상황 | 확인한 결과 |
| --- | --- |
| 회원 코드 발급 실패 | 오류 안내가 표시되고 선택한 파트를 유지한 채 재시도할 수 있음 |
| 무한 스크롤의 다음 페이지 실패 | 기존 글 10개가 남고 자동 추가 요청이 멈춤 |
| API 정상화 후 재시도 | 기존 글에 다음 10개가 이어지고 마지막 페이지 안내가 표시됨 |
| 이전 검색은 1.5초 지연, 다음 검색은 즉시 응답 | 늦은 이전 응답이 도착한 뒤에도 다음 검색 결과만 표시됨 |
| 수정 요청에 403 응답 | 서버의 거절 안내가 표시되고 입력한 제목·본문이 유지됨 |

## 재시도 조건 변경

목록 조회에는 기본 재시도 설정이, 상세 조회에는 별도 설정이 적용되고 있었습니다.
공통 QueryClient에서 4xx는 재시도하지 않고, 나머지 오류는 최대 두 번 재시도하도록 맞췄습니다.

QueryObserver에 오류를 발생시키는 요청 함수를 연결해 호출 횟수를 비교했습니다.
Node에서는 브라우저와 기본값이 달라 이전 브라우저 정책은 retry: 3으로 지정했고,
변경 후 정책은 실제 src/lib/queryClient.ts를 불러와 확인했습니다.
횟수만 비교하기 위해 이 검증의 재시도 대기 시간은 0으로 설정했습니다.

| 응답 | 변경 전 정책의 호출 횟수 | 현재 설정의 호출 횟수 |
| --- | --- | --- |
| 400 | 4 | 1 |
| 401 / 403 / 404 | 비교하지 않음 | 각 1 |
| 503 | 비교하지 않음 | 3 (최초 1회 + 재시도 2회) |

기본 재시도와 설정 방법은 [TanStack Query 공식 문서](https://tanstack.com/query/latest/docs/framework/react/guides/query-retries)를 참고했습니다.

모의 응답으로 확인한 결과이며, 실제 서버 장애나 운영 환경에서 같은 상황을 발생시킨 것은 아닙니다.

## 수정 후 화면 갱신

수정 성공 시 상세 캐시와 이미 조회한 목록의 해당 글을 서버 응답으로 먼저 바꾸도록 수정했습니다.
진행 중이던 조회는 취소하고, 화면에 없는 목록도 다시 조회해 제목 검색 결과를 맞춥니다.

- 모의 API를 연결한 브라우저에서 제목·본문을 수정한 뒤, 새로고침 없이 상세와 목록에 변경된 값이 표시되는 것을 확인했습니다.
- 실제 useUpdatePost의 성공 콜백과 QueryClient를 연결한 별도 검증에서는 조회 응답을 지연시켰습니다. 응답 전에도 상세와 목록 두 번째 페이지의 글이 바뀌고, 기존 데이터 객체와 pageParams는 유지되는 것을 확인했습니다.
- 화면에 없는 검색 캐시도 다시 조회되어 이전 제목의 검색 결과에서는 빠지고 새 제목의 검색 결과에는 포함되는 것을 확인했습니다. 검색 조건을 유지한 상세 이동은 재조회 후 실행됐습니다.

검증용 스크립트와 모의 서버는 임시 폴더에서 실행했으며, 실제 API의 게시글은 변경하지 않았습니다.
